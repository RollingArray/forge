# Experiment 020-A: Declarative Generation Specification Foundation

## 1. What were we trying to prove?

**In simple terms**

Before FORGE can generate data, we need a way to tell it what data we want.

Instead of writing custom Python code for every dataset, we want to describe the dataset using a structured specification. For example:

```text
Create Customers
  ├── Customer ID
  ├── Customer Score
  └── Customer Value

Create Orders
  ├── Order ID
  ├── Customer ID
  └── Order Value
```

The first question was:

> **Can FORGE understand and validate this kind of declarative specification before it tries to generate anything?**

---

## 2. What did we actually do?

We gave FORGE a versioned specification and asked it to validate all of the things that the specification claims to describe.

The specification contained:

* 6 entities
* fields and their types
* relationships
* generation rules
* statistical behavior
* scenarios
* validation requirements
* provenance configuration
* reproducibility configuration

We also gave the experiment a fixed random seed:

```text
Seed:          42
Random stream: FORGE-020
Scenario:      NORMAL
```

This means the experiment was intentionally controlled and repeatable.

---

## 3. What happened?

**Everything passed.**

```text
Specification structure          PASS
Vocabulary                       PASS
Entities and fields              PASS
Relationships                    PASS
Rules                            PASS
Statistical behavior             PASS
Scenarios                        PASS
Validation configuration         PASS
Provenance configuration         PASS
Reproducibility configuration    PASS
```

**Overall: PASS**

In plain English:

> FORGE successfully understood the specification, confirmed that the things referenced by the specification were valid, and established a deterministic generation context.

---

## 4. What does that actually mean?

This experiment did **not** generate a useful dataset yet.

What we proved was something more fundamental.

We proved that we can give FORGE a structured description of a dataset and have FORGE answer:

> "Yes, I understand what you are asking me to generate, and the specification follows the rules I understand."

Think of it like a blueprint.

Before building a house, you first want to know that the blueprint is valid.

**020-A validated the blueprint.**

It did not build the house yet.

---

## 5. Why is this important?

Without this foundation, every new dataset would potentially require custom generation code.

That would look like:

```text
New dataset
    ↓
Write custom Python
    ↓
Debug custom Python
    ↓
Change Python when requirements change
    ↓
Write more Python
```

The direction we are testing with FORGE is:

```text
New dataset
    ↓
Write / modify specification
    ↓
FORGE understands specification
    ↓
FORGE generates according to specification
```

That is the architectural idea behind the entire 020 series.

---

## 6. What did we learn?

The important learning from 020-A is:

> **A declarative specification can become the stable contract between what a user wants and how FORGE eventually generates it.**

We also established something else early:

**Reproducibility is part of the design.**

The experiment explicitly defined:

```text
Seed = 42
Random stream = FORGE-020
Deterministic = True
```

So we are not treating repeatability as something to bolt on at the end.

---

## 7. What has NOT been proven yet?

This is important.

020-A does **not** prove that:

* FORGE can generate records.
* The generated records will be realistic.
* Relationships will actually work.
* Constraints will be satisfied.
* Statistical distributions will be correct.
* Generated data will be useful for an actual engineering use case.

Those questions are deliberately left for later experiments.

---

## 8. Architectural outcome

### Before 020-A

We had the idea:

> "Synthetic data should be specification-driven."

### After 020-A

We have experimentally validated:

> **FORGE has a versioned and validated specification contract that can describe generation intent and establish a deterministic generation context.**

That gives the next experiments something concrete to build on.

---

## 9. Resulting FORGE capability

**FORGE can understand and validate a structured description of the dataset we want to create before attempting generation.**
