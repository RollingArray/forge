# Experiment 020-R.1: Unified Feasibility and Joint Generation

## 1. What were we trying to prove?

R showed that independently working capabilities could not yet be composed reliably.

R.1 therefore introduced a new model:

```text
Specification
      ↓
Requirement extraction
      ↓
Unified feasibility analysis
      ↓
Joint generation planning
      ↓
Direct generation
      ↓
Independent validation
```

The key idea is:

> **Don't generate statistics and then try to satisfy constraints afterward. Determine what is feasible first, then generate directly inside that feasible space.**

That is the right architectural move.

# 6. What "constraint preservation" means here

The intended contract is:

```text
Constraint
    ↓
Feasible region
    ↓
Generation
    ↓
Every generated value satisfies constraint
```

But R.1 has apparently produced:

```text
Constraint
    ↓
Feasible region
    ↓
Generation
    ↓
At least one value violates constraint
```

That is the remaining defect.

And this is important because the whole purpose of the unified feasibility model is defeated if the generator doesn't actually honor the region it computed.

# 8. This narrows the problem considerably

The remaining problem is likely somewhere around:

```text
Unified feasible region
          ↓
     translation
          ↓
     field generator
```

In other words:

> **The system knows what is feasible, but the constraint-derived region is not yet being enforced correctly by the sampling mechanism.**

That's a much more precise architectural problem than the one we had in R.

---

# 9. This is exactly why R.2 makes sense

R.2 moves the problem one level deeper.

Instead of asking:

> "Can the whole dataset be generated from a unified feasible model?"

R.2 asks:

> **"Can we compute the feasible region for each individual record and generate the target directly inside that region?"**

That's a much more concrete formulation.

For example:

```text
CUSTOMER_SCORE = 20
        ↓
CREDIT_LIMIT must be
[1000, 10000]
```

versus:

```text
CUSTOMER_SCORE = 60
        ↓
CREDIT_LIMIT must be
[3000, 10000]
```

The feasible region changes with the context.

That's exactly the problem we need to solve.

> **R.1 demonstrates that unified feasibility analysis and joint generation can successfully compose statistical relationships, conditional rules, derived fields, dependency planning, and deterministic execution. The remaining limitation is constraint preservation during direct sampling, indicating that feasible-region computation and generation are not yet fully coupled at the record level.**

That is a very strong architectural conclusion.
