# Experiment 023: Population Planning

**Status:** In Progress

**Experiment Type:** Foundational / Structural / Relationship / Validation

**FORGE Area:** Population Planning

**Objective:** Determine whether the entity populations defined in a FORGE specification are feasible based on relationship requirements and foreign-key identity capacity.

---

## 1. Research Question

Can FORGE independently analyze the populations requested in a specification and determine the minimum, maximum, resolved, and feasibility status of each entity population before synthetic data generation begins?

---

## 2. Hypothesis

FORGE can determine population feasibility before generation by analyzing the constraints already expressed in the specification.

The hypothesis assumes:

* Explicit population values are authoritative user inputs.
* Relationship cardinalities can establish minimum population requirements.
* Foreign keys that cover complete entity identities can establish key-capacity limits.
* `AUTO` populations can be resolved when sufficient constraints exist.
* Population planning can be performed independently of synthetic data generation.

The experiment intentionally does not assume that every population can be automatically determined.

The hypothesis will be rejected if FORGE cannot reliably identify infeasible population combinations, derive the expected population constraints, or distinguish between feasible, infeasible, and unresolved populations.

---

## 3. Scope

This experiment will evaluate population planning as an independent stage between specification authoring and specification execution.

### Included

* Loading the authoritative specification produced by Experiment 022
* Extracting entity population definitions
* Analyzing relationship-derived population requirements
* Analyzing foreign-key identity capacity
* Deriving minimum and maximum feasible populations
* Evaluating explicit population requests
* Resolving `AUTO` populations where sufficient constraints exist
* Producing a population plan and feasibility analysis

### Excluded

* Synthetic data generation
* Generated dataset validation
* Constraint execution during data generation
* Data repair or correction
* Statistical distribution generation
* Dataset performance benchmarking
* Modification of the source specification

These capabilities may be explored in later experiments.

## 4. Initial Dataset / Entity

The experiment consumes the authoritative FORGE specification generated by Experiment 022.

```text
experiments/022_llm_assisted_specification_authoring/output/specification.json
```

The specification contains multiple related entities and is used to evaluate population planning across entity relationships and foreign-key dependencies.

The dataset remains domain-neutral at the population-planning level. Entity names and fields are treated as metadata rather than as domain-specific generation rules.

### Entity

The experiment uses the entities defined in the specification:

```text
KNA1
MARA
VBAK
VBAP
VBPA
ADRC
VBAK_STATUS
VBEP
```

### Fields

Population planning does not generate field values. Identity fields are used to determine foreign-key capacity.

| ----------- | ---------------- | ------------------------- |
| KNA1        | `KUNNR`          | Parent entity             |
| MARA        | `MATNR`          | Independent entity        |
| VBAK        | `VBELN`          | Parent entity             |
| VBAP        | `VBELN`, `POSNR` | Child entity              |

| ADRC        | `ADDRNUMBER`     | Parent entity             |
| VBAK_STATUS | `VBELN`          | Related one-to-one entity |

## 5. Experiment Configuration

Population definitions are supplied as part of the FORGE specification.

Example:

```json
{
  "entities": [
    {
      "name": "KNA1",
      "population": {
        "count": 20
      }
    },
    {
      "name": "VBAP",
      "population": {
        "count": 20
      }
    }
  ]
}
```

An entity may also use `AUTO`:

```json
{
  "name": "VBAP",
  "population": {
    "count": "AUTO"
  }
}
```

The planner derives additional constraints from relationships and foreign keys.

For example:

```text
VBEP.(VBELN, POSNR)
        │
        ▼
VBAP.(VBELN, POSNR)
```

When the foreign key covers the complete identity of both entities, the available `VBAP` identity keys constrain the maximum `VBEP` population.

The population planner does not modify explicit user requests to make them feasible.

## 6. Expected Outputs

The experiment is expected to produce a population plan containing:

* Requested population
* Population mode
* Minimum feasible population
* Maximum feasible population where applicable
* Resolved population
* Feasibility status
* Reason for the resulting status
* Recommendation where applicable
* Relationship-derived requirements
* Foreign-key capacity requirements
* Foreign-key capacity limits

The plan is persisted at:

```text
experiments/023_population_planning/output/population_plan.json
```

A human-readable population analysis is also printed to the console.

---

## 7. Success Criteria

The experiment is considered successful if FORGE can:

1. Load the Experiment 022 specification directly.
2. Extract all entity population definitions.
3. Derive relationship-based population requirements.
4. Derive foreign-key capacity constraints where applicable.
5. Identify feasible explicit populations.
6. Identify infeasible explicit populations.
7. Resolve `AUTO` populations when sufficient constraints exist.
8. Leave populations unresolved when insufficient information exists.
9. Produce a persistent population plan without modifying the source specification.
10. Operate independently of the generation package.

## 9. Experiment Boundary

Experiment 023 is responsible only for determining the population plan.

```text
022 Specification Authoring
          │
          ▼
023 Population Planning
          │
          ▼
024 Specification Execution
          │
          ├── Generation
          └── Validation
```

Population planning does not generate, repair, or validate synthetic records.

The output of this experiment is a planning artifact that can be consumed by the subsequent execution stage.

---

## 10. Run the Experiment

Run Experiment 023 from the FORGE repository root:

```bash
python experiments/023_population_planning/app.py
```

The experiment:

1. Loads the authoritative specification from Experiment 022.
2. Builds the population planning inputs.
3. Analyzes relationship requirements.
4. Analyzes foreign-key identity capacity.
5. Evaluates population feasibility.
6. Resolves `AUTO` populations where possible.
7. Prints the population analysis to the console.
8. Writes the population plan to:

```text
experiments/023_population_planning/output/population_plan.json
```

The output directory is created automatically if it does not already exist.

To verify the generated artifact:

```bash
ls -lh experiments/023_population_planning/output/
```

Expected output:

```text
README.md
population_plan.json
```
